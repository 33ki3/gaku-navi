# todo 管理

`.github/todo/todo.md` を単一の todo ファイルとして扱う。未完了タスクの整理・再開を依頼された場合、今回の依頼が既存 todo に関係する場合、またはコード中の `Q:` / `TODO:` を処理する場合だけ読む。

## セクション

todo は次の4セクションで管理する。

- **対応中タスク**: `- [ ] タスク名: 対応内容の詳細`。実装と検証が終わったら `[x]` にし、作業中は削除しない。
- **保留中のタスク**: 将来対応する項目。ユーザーの依頼なしに着手せず、着手時に対応中へ移す。
- **Q&A管理**: ユーザーへの回答が必要なコード中の `Q:` だけを記録する。
- **追加の指示**: ユーザー記入欄。今回の依頼に関係し、継続管理が必要な内容だけ対応中へ移す。

## 作業手順

1. 関連する対応中タスクと追加の指示を確認する。
2. 依頼に関係する追加の指示だけを対応中タスクへ移す。
3. 関連タスクを実装・検証する。完了後すぐに `[x]` へ更新する。
4. コード内の `Q:` / `TODO:` を検索し、今回の依頼に関係する未対応項目を処理する。
5. 関連する追加の指示、対応中タスク、Q&Aを再確認する。
6. 完了済みタスクと、ユーザーが解決済みにした Q&A を `.github/todo/archive/YYYYMMDD.md` へ追記し、todo から削除する。同日分は既存ファイルへ追記する。

無関係な todo 項目には着手しない。Q&A のチェック状態や整理はユーザーの判断なしに変更しない。

## コード中の質問

- 実装だけで解決できる `Q:` は対応中タスクとして処理し、コードから削除する。
- 調査報告や設計判断などユーザーへの回答が必要な `Q:` は、コードから削除して Q&A 管理へ `- [ ] Q:` と `A:` を記録する。
- 回答文やレビュー相手へのメッセージをコードコメントへ残さない。
- Q&A の末尾に対象箇所を `（[src/path/file.ts:行番号](../../src/path/file.ts#L行番号)）` 形式で付ける。複数箇所はカンマで区切る。
- ユーザーが `A:` の下へフォローアップ `Q:` を追加した場合は、同じインデントで `A:` を追記する。

```markdown
- [ ] Q: 質問テキスト
  - A: 回答テキスト（[src/file.ts:行](../../src/file.ts#L行)）
    - Q: フォローアップ質問
      - A: フォローアップ回答
```
